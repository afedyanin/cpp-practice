# Представимые числа (representable values) 

Представимые числа (representable values) в C++ — это конкретный набор числовых значений, которые данный тип данных способен точно хранить в памяти без потери точности или переполнения.
Поскольку каждый тип имеет фиксированный размер в битах, количество возможных комбинаций нулей и единиц ограничено, что задаёт строгие рамки для этих чисел.

Сравнение основных типов (на стандартных 64-битных платформах)


- int 32 бита (4 байта)	От -2 147 483 648 до 2 147 483 647	Хранит все целые числа в этом диапазоне абсолютно точно.
- float	32 бита (4 байта) От ±1.17 × 10⁻³⁸ до ±3.40 × 10³⁸	6–7 значащих цифр. Хранит числа с «пробелами» между ними.
- double 64 бита (8 байт) От ±2.22 × 10⁻³⁰⁸ до ±1.79 × 10³⁰⁸	15–17 значащих цифр. Намного плотнее покрывает числовую ось, чем float.

## Как устроены представимые числа для каждого типа


### 1. Целочисленный тип (int)

- Сплошное покрытие: Внутри своего диапазона тип int представляет абсолютно каждое целое число без пропусков (шаг всегда равен 1).
- Переполнение: Если попытаться записать число больше максимального (2 147 483 647), произойдёт переполнение, которое в C++ приводит к неопределённому поведению (Undefined Behavior).

### 2. Типы с плавающей точкой (float и double)

Эти типы используют стандарт IEEE 754 и работают как научная запись числа: \(\text{мантисса} \times 2^{\text{порядок}}\). Из-за этого у них есть важные особенности:
- Неравномерная плотность: Представимые числа распределены не равномерно. Около нуля они расположены очень плотно, но чем дальше от нуля (чем больше число), тем шире становятся «пробелы» между соседними представимыми значениями.
- Потеря точности на больших числах: Например, для float после числа \(16\,777\,216\) (\(2^{24}\)) шаг между соседними представимыми числами становится равен \(2\). Это значит, что число \(16\,777\,217\) в float вообще непредставимо — оно округлится до ближайшего соседа.
- Проблема десятичных дробей: Компьютер считает в двоичной системе. Простая десятичная дробь вроде 0.1 в двоичной системе превращается в бесконечную периодическую дробь, поэтому она не является точно представимой ни во float, ни в double. В память записывается ближайшее к ней представимое число.
- Специальные значения: Помимо обычных чисел, к представимым значениям float и double относятся +0.0, -0.0, бесконечности (+inf, -inf) и NaN (не число).


## ULP 

(Units in the Last Place, «единица в младшем разряде») — это расстояние между двумя ближайшими соседними представимыми числами с плавающей точкой для заданного значения. По сути, 1 ULP — это минимально возможный шаг (цена деления) в конкретной точке числовой оси.

### Почему ULP меняется в зависимости от числа

Поскольку числа с плавающей точкой хранятся в экспоненциальной форме (\(\text{мантисса} \times 2^{\text{порядок}}\)), величина 1 ULP не является константой и растёт вместе с ростом самого числа:
- Для float (24 бита мантиссы): вокруг числа 1.0 шаг 1 ULP равен \(2^{-23} \approx 1.19 \times 10^{-7}\) (это значение называют машинным эпсилоном).
- Вокруг числа 1 000 000.0: порядок числа увеличивается, поэтому шаг 1 ULP для float вырастает до \(0.0625\).
- Вокруг числа 16 777 216.0 (\(2^{24}\)): 1 ULP для float становится равен ровно 1.0, а после него — 2.0. Дробных чисел в этом диапазоне больше не существует.

### Как определить величину 1 ULP для конкретного числа

В современных версиях C++ и C# не нужно вычислять ULP вручную по формулам — для этого есть встроенные функции, возвращающие следующее или предыдущее представимое число (nextafter / BitIncrement). Величина 1 ULP равна разности между соседним и текущим числом.

``` cpp
cpp
#include <cmath>
#include <limits>
#include <iostream>

double getUlp(double x) {
    // Находим следующее представимое число в сторону бесконечности
    double next = std::nextafter(x, std::numeric_limits<double>::infinity());
    return next - x;
}
```

```csharp

double getUlp(double x)
{
    // Возвращает наименьшее представимое число, которое больше x
    double next = Math.BitIncrement(x);
    return next - x;
}

```

### Как посчитать расстояние в ULP между двумя числами (алгоритм сравнения)

Главная практическая польза ULP — сравнение двух чисел. 
Если два числа отличаются на 1–4 ULP, это почти наверняка одна и та же величина с небольшой погрешностью округления.
Благодаря особенностям стандарта IEEE 754, если интерпретировать битовое представление двух положительных чисел (float или double) как обычные целые числа (int32_t или int64_t), то разница между этими целыми числами будет равна точному количеству ULP (шагов) между ними.

Реализация подсчёта ULP в C#

``` cs
csharp
using System;

public static class UlpComparer
{
    public static long GetUlpDistance(double a, double b)
    {
        // Особые случаи (NaN, бесконечности) требуют отдельной проверки
        if (double.IsNaN(a) || double.IsNaN(b)) return long.MaxValue;
        
        // Переводим 64 бита double в 64-битное целое число
        long bitsA = BitConverter.DoubleToInt64Bits(a);
        long bitsB = BitConverter.DoubleToInt64Bits(b);

        // Корректируем отрицательные числа (перевод из прямого кода в дополнительный)
        if (bitsA < 0) bitsA = long.MinValue - bitsA;
        if (bitsB < 0) bitsB = long.MinValue - bitsB;

        return Math.Abs(bitsA - bitsB);
    }

    public static bool AlmostEqualUlp(double a, double b, int maxUlps = 4)
    {
        return GetUlpDistance(a, b) <= maxUlps;
    }
}
```

Реализация подсчёта ULP в C++ (C++20 с std::bit_cast)

``` cpp
#include <bit>
#include <cstdint>
#include <cmath>
#include <limits>

int64_t getUlpDistance(double a, double b) {
    if (std::isnan(a) || std::isnan(b)) return std::numeric_limits<int64_t>::max();

    auto bitsA = std::bit_cast<int64_t>(a);
    auto bitsB = std::bit_cast<int64_t>(b);

    // Приводим отрицательные числа к линейной шкале целых чисел
    if (bitsA < 0) bitsA = std::numeric_limits<int64_t>::min() - bitsA;
    if (bitsB < 0) bitsB = std::numeric_limits<int64_t>::min() - bitsB;

    return std::abs(bitsA - bitsB);
}
```

### Главный подвох метода ULP (около нуля)

Сравнение по ULP плохо работает вблизи 0.0.

- Около нуля представимые числа упакованы невероятно плотно (шаг равен примерно \(5 \times 10^{-324}\) для double).
- Если в результате вычислений вместо чистого 0.0 у вас получилось число 1e-16 (крошечная погрешность), расстояние между ними составит миллиарды ULP, хотя фактически они почти равны.

Решение: на практике сравнение в ULP всегда комбинируют с проверкой на абсолютный эпсилон около нуля (Math.Abs(a - b) <= 1e-12), и только если числа далеки от нуля, считают расстояние в ULP.


## Почему в типе float за числом 1_000_000_000 сразу идет 1_000_000_064 без промежуточных значений?

В типе float за числом 1_000_000_000 сразу идёт 1_000_000_064, потому что на этом масштабе цена деления самого младшего бита мантиссы (1 ULP) равна ровно 64. 
В 32-битном float просто физически не хватает битов, чтобы записать более мелкие прибавки к миллиарду.

### Математика и битовая механика этого скачка

Чтобы увидеть, откуда берётся число 64, разберём устройство float по стандарту IEEE 754.

#### 1. Из чего состоит float (32 бита)

- 1 бит — знак (0 для плюса).
- 8 бит — порядок (степень двойки, задающая масштаб числа).
- 23 бита — дробная часть мантиссы. Плюс всегда подразумевается 1 скрытый ведущий бит (1.xxxx... в двоичной системе). 

Итого: 24 значащих двоичных разряда точности.

### 2. Определяем масштаб (порядок) для миллиарда

Компьютер подбирает ближайшую степень двойки, которая меньше или равна 1_000_000_000:
- \(2^{29} = 536\,870\,912\)
- \(2^{30} = 1\,073\,741\,824\) (уже перебор)

Значит, для записи миллиарда float выбирает порядок \(2^{29}\) и представляет число по формуле:
\(\text{Число}=2^{29}\times (1+\text{дробная часть мантиссы})\)

### 3. Вычисляем цену одного шага (1 ULP)

Мантисса имеет 23 бита после двоичной точки. Минимальное изменение, которое можно сделать в мантиссе — это изменить самый последний, 23-й бит с 0 на 1. Его вес равен \(2^{-23}\).

Умножаем вес этого младшего бита на текущий порядок числа (\(2^{29}\)):
\(\text{Шаг (1 ULP)}=2^{29}\times 2^{-23}=2^{29-23}=2^{6}=\mathbf{64}\)

Почему первым числом стал именно 1_000_000_000

Сам миллиард удачно делится на 64 без остатка (\(1\,000\,000\,000 / 64 = 15\,625\,000\)). 
Это значит, что его двоичная запись умещается в 24 значащих бита без потерь:

- Биты 1_000_000_000: мантисса заканчивается на ...0011000
- Прибавляем +1 к младшему биту: мантисса становится ...0011001
- Новое значение: \(1\,000\,000\,000 + 64 = \mathbf{1\,000\,000\,064}\)

Все числа между ними (например, 1_000_000_001 или 1_000_000_030) требуют 25-го, 26-го и более младших битов, которых во float нет. 
При попытке записать 1_000_000_020f процессор округлит его до ближайшего кратного 64, то есть обратно до 1_000_000_000f.

Как шаг (1 ULP) растёт с увеличением степени двойки

Каждый раз, когда число перешагивает очередную степень двойки, цена младшего бита удваивается:

Диапазон чисел во float	Степень двойки (порядок)	Формула шага (1 ULP)	Шаг между соседними числами
- От \(8\,388\,608\) до \(16\,777\,216\)	\(2^{23}\)	\(2^{23 - 23} = 2^0\)	1 (последний диапазон, где есть все целые числа)
- От \(16\,777\,216\) до \(33\,554\,432\)	\(2^{24}\)	\(2^{24 - 23} = 2^1\)	2 (остаются только чётные числа)
- От \(268\,435\,456\) до \(536\,870\,912\)	\(2^{28}\)	\(2^{28 - 23} = 2^5\)	32
- От \(536\,870\,912\) до \(1\,073\,741\,824\)	\(2^{29}\)	\(2^{29 - 23} = 2^6\)	64 (здесь находится наш миллиард)
- От \(1\,073\,741\,824\) до \(2\,147\,483\,648\)	\(2^{30}\)	\(2^{30 - 23} = 2^7\)	128

Примечание: В типе double под мантиссу выделено 52 бита (53 значащих разряда), поэтому на уровне миллиарда (\(2^{29}\)) шаг там равен \(2^{29 - 52} = 2^{-23} \approx 0.000000119\), 
и такой грубой потери точности не происходит.

=================

При сохранении в 32-битный формат float (IEEE 754) число 1 000 000 027 теряет сразу 6 младших разрядов и округляется до ровного миллиарда — 1 000 000 000. 
В памяти оно записывается как 0 10011100 11011100110101100101000 (0x4E6E6B28).

Пошаговый перевод числа в IEEE 754

Шаг 1. Перевод в двоичную систему. 
Число 1 000 000 027 находится между \(2^{29}\) (\(536\,870\,912\)) и \(2^{30}\) (\(1\,073\,741\,824\)). 
В двоичном виде оно занимает 30 бит: 111011100110101100101000011011

Шаг 2. Нормализация. 
Сдвигаем двоичную точку влево на 29 позиций, чтобы перед ней осталась одна ведущая единица:
1.11011100110101100101000011011 × 2²⁹

Шаг 3. Округление до 23 бит мантиссы. 
В float помещаются только первые 23 знака после точки (11011100110101100101000). 
Остальные 6 младших битов (011011, что равно 27 в десятичной системе) не помещаются. 
Поскольку первый отбрасываемый бит равен 0, происходит округление вниз — хвост просто отрезается.

Шаг 4. Вычисление экспоненты. Степень двойки равна 29. 
Прибавляем стандартное смещение 127: 29 + 127 = 156. 
В двоичной системе число 156 записывается как 10011100.

В диапазоне от \(2^{29}\) до \(2^{30}\) шаг между соседними представимыми числами во float равен \(2^{29 - 23} = 2^6 = \mathbf{64}\). 
То есть в районе одного миллиарда формат float способен хранить только числа, 
кратные 64 (1 000 000 000, 1 000 000 064, 1 000 000 128 и так далее).
