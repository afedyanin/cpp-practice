# Стандарты форматирования и стиля (Style Guides)

Эти документы описывают именование переменных, расстановку отступов, использование пробелов и безопасные практики языка.

### C++ Core Guidelines. 

Это главный современный справочник, который поддерживают Бьярне Страуструп и Герб Саттер. 
Документ фокусируется не только на оформлении, но и на написании безопасного и современного кода. 
Найти его можно в официальном репозитории [isocpp/CppCoreGuidelines на GitHub](https://github.com/isocpp/CppCoreGuidelines).

### Google C++ Style Guide

Один из самых популярных и строгих стандартов в индустрии. 
Он подробно регламентирует оформление заголовков, именование функций, порядок включения файлов и правила работы с памятью.
- [https://github.com/google/styleguide](https://github.com/google/styleguide)


### LLVM Coding Standards 

Стандарт от разработчиков компилятора Clang и инфраструктуры LLVM. 
Отлично подходит для системного программирования и высоконагруженных проектов.

### JSF Air Vehicle C++ Coding Standards

Строгий стандарт, созданный для авиационной промышленности (Lockheed Martin). 
Полезен для изучения правил написания максимально надежного кода.

## Организация файлов и структура проекта

Универсальной структуры папок тоже нет, но в сообществе сложился де-факто стандарт, который поддерживают популярные системы сборки.

### The Pitchfork Layout (PFL) 

Это спецификация, описывающая стандартную структуру директорий для C++ проектов (src/, include/, tests/, build/, docs/). 
Она помогает легко подключать сторонние библиотеки и настраивать сборку. 
Спецификация доступна в открытом репозитории [vector-of-bool/pitchfork на GitHub](https://github.com/vector-of-bool/pitchfork).

### Документация CMake и Modern CMake 

В официальной документации CMake и руководствах вроде [An Introduction to Modern CMake](https://gitlab.com/CLIUtils/modern-cmake) подробно разбирается, 
как правильно разделять заголовочные файлы (.hpp) и исходники (.cpp), а также как организовывать модули и цели сборки.

### Структура репозиториев крупных библиотек 

Хорошей практикой считается изучение открытого кода современных библиотек. 
Например, можно посмотреть на организацию файлов в проектах fmt (форматирование строк), nlohmann/json или spdlog.

## Инструменты автоматизации

Вместо ручного соблюдения правил форматирования в C++ принято использовать автоматические инструменты.

### Clang-Format 

Утилита, которая автоматически форматирует код по заданному файлу конфигурации (.clang-format). 
Она поддерживает встроенные пресеты для стилей Google, LLVM, Mozilla, WebKit и Microsoft.

### Clang-Tidy

Статический анализатор, который проверяет код на соответствие правилам C++ Core Guidelines, находит потенциальные баги и подсказывает, как улучшить стиль.
